# 다음 작업자를 위한 인수인계

## 최신 상태부터 확인

현재 주 작업 대상은 **워치 케어 0.4.0 원본 UI 로컬 테스트판**입니다. [현재 상태](CURRENT_STATUS.md)와 [커스터마이징 가이드](WATCH_CARE_CUSTOMIZATION.md)를 먼저 읽으세요. 원본 화면과 SDK로 실기기 등록·심박 및 걸음 데이터 표시를 확인했습니다. 독립 센서 앱을 계속 확장하는 대신 원본 UI·기능을 유지하며 수정하는 것이 사용자의 최신 요청입니다.

아래 내용에는 초기 분석 단계의 이력이 포함됩니다. 과거의 미검증 상태나 기본 빌드 프로필을 현재 결과와 혼동하지 않습니다. 현재 권장 빌드는 최신 APK를 작업 기준으로 푼 뒤 `scripts/Build-WatchCare.ps1`을 사용하는 경로입니다.

## 사용자 목표

1. SMART-TIME PRO를 최대한 읽고 수정할 수 있는 형태로 복원.
2. 커스터마이징 가능한 범위를 자세히 정리.
3. Diz-SW01 연결을 유지하며 자체 앱으로 발전시킬 가능성 검토.
4. 내려받아 설치 시험할 APK 제공.
5. 코드·진행 방법·APK를 이 GitHub 저장소에 보관.

## 완료한 작업

- XAPK 구조·DEX·리소스·네이티브·매니페스트 추출.
- 전체 Smali와 읽기용 Java, 앱·연결 SDK의 단순 흐름 보조 Java 복원.
- 자동 별칭 매핑, 전체 클래스·컴포넌트·리소스·네이티브 심볼 인덱스 생성.
- 분할 APK 세 개 모두 재조립 성공.
- ARM64 단일 APK 통합, 서명 v2·v3·ZIP 정렬 검증.
- 원본 리소스 ID와 클래스·네이티브 보존 검증.
- 수정 범위 25개 영역, 작업 공간과 오버레이 방식, 빌드·테스트 문서 작성.
- 사용자 추가 요청에 따라 `Diz SW01 Custom` / `com.diz.sw01.custom` 별도 식별자 빌드 생성. Provider·자체 권한·표시 이름·버전을 분리했고 DEX·네이티브·리소스 ID 보존을 검증했습니다. [변경 기록](CUSTOM_APP_IDENTITY.md)을 참고하세요.

## 아직 하지 않은 작업

- 사용자 기기에서 보고된 ‘악성 앱으로 의심’ 설치 차단의 원인 확인 및 공식 검토. 현재 APK 설치는 보류합니다. [조사 기록](SECURITY_BLOCK.md)을 먼저 확인하세요.
- 실제 Android 기기에 설치·실행.
- 새 서명에서 Diz-SW01 검색·연결·서버 바인딩·동기화 확인.
- 특정 UI·기능에 대한 제품 커스터마이징.
- 모든 난독화 이름의 의미 복구, 모든 Java 복원 오류 수정.
- 네이티브 C/C++ 소스, 제조사 서버, 워치 펌웨어 복원.
- 별도 앱 ID에서의 실제 설치·실행·외부 SDK 등록·서버 인증 검증, 자체 계정·자체 클라우드 전환.
- 스토어 게시 또는 제조사 코드·SDK 이용 권한 확보.

## 권장하는 다음 작업

먼저 사용자 기기에서 발생한 보안 차단의 판정 주체와 원인을 확인하고 필요한 코드·권한 검토 및 공식 판정 재검토를 진행합니다. 설치가 승인되고 안전성 검토를 마친 후 ARM64 휴대폰에서 앱 실행과 Diz-SW01 연결·시간 동기화를 확인합니다. 성공하면 한국어 문구나 색상 한 항목처럼 범위가 작은 변경을 적용해 빌드·설치·업데이트 경로를 검증합니다. 이후 홈 화면, 기기 설정, 워치페이스를 순서대로 변경합니다.

연결 실패 시 원본 앱과 테스트 앱의 동작을 같은 조건에서 비교합니다. 서명·권한·서버·모델 분기를 먼저 확인하고 통신 프로토콜을 추측해서 바꾸지 않습니다. 실기기 증거 없이 UUID·인증 절차·칩셋을 확정하지 않습니다.

독립 상용 제품이 목표라면 기존 APK 수정과 별개로 자체 Android 소스 프로젝트, 사용 가능한 제조사 SDK, 서버·계정·콘텐츠 권한을 검토합니다. 현재 복원 Java는 바로 재컴파일 가능한 원본 프로젝트가 아닙니다.
